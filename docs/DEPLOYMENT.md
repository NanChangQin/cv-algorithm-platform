# 模型定向部署

把算法版本部署到指定服务器的指定 GPU，平台负责把运行所需的镜像和权重准备好，再启动实例。

## 使用

- **算法库 → 版本详情 → 部署到服务器**，或 **模型部署 → 新建部署**：选择算法版本、服务器和 GPU（GPU 选“自动”时使用空闲显存最多的一张）。
- 部署卡片上依次显示四个步骤的进度和结果：
  1. **检查服务器**：能否连接、所选 GPU 是否存在、空闲显存是否低于算法要求（只提醒，不阻止）。
  2. **准备镜像**：服务器上已有镜像就跳过；否则从其他已有该镜像的服务器传输（显示已传输量和速度）；都没有时，如果这个版本是导入的算法包，就把算法包传到目标服务器并在那里构建。
  3. **准备权重**：训练发布的模型从主服务器上传自己的权重（已有且校验值一致时跳过）；其他算法检查服务器上 `models/<算法 ID>` 目录，没有时从其他服务器复制（逐个文件校验 SHA-256），都没有时按“镜像自带权重”跳过。
  4. **启动实例**：启动容器并等待健康检查通过。
- 失败时显示失败的步骤和原因；可以 **启动**（重新执行一遍步骤，已就绪的部分会直接跳过）、**停止**（停止容器，保留部署）、**重新部署**（删除容器后重新执行全部步骤）或 **删除**。
- 同一个算法版本可以部署到多台服务器、多张 GPU。**工作台 → 运行位置 → 部署实例** 可以选择在哪个部署上推理；部署页面的“去工作台测试”会直接选好。也可以在创建任务的接口里传 `deployment_id`，部署没在运行时拒绝。
- 运行中的部署每分钟检查一次实例，同时刷新实例的最近使用时间，所以不会被空闲回收；实例被删除或退出时部署标为失败并提示原因。
- 部署的创建和启停需要算法开发者或管理员权限；所有人都能看到部署列表，以便在工作台里选择。

## 传输方式

主服务器在节点之间中转：从源节点的 Algorithm Manager 读取（`docker save` 流或权重文件），同时写到目标节点，不在主服务器落盘。目标节点只接受与请求的镜像名完全一致、并且以 `cv-platform/` 开头的算法镜像（镜像文件里夹带其他标签会被拒绝，平台服务镜像不能导入）。权重写入前核对 SHA-256，路径不能越出模型目录。

镜像传输量就是镜像大小，几 GB 的 PyTorch 镜像在千兆局域网上需要几分钟，Wi-Fi 下会慢很多。

## 服务器准备

- 主平台和各节点都要更新 Algorithm Manager（新增镜像导出/导入、算法包接收和权重目录接口）。旧版 Manager 会提示“版本过旧，请先更新”。
- Manager 需要挂载本机的模型目录：`compose.yaml` 已挂载 `${CV_PLATFORM_MODEL_ROOT}:/models`，`compose.gpu-node.yaml` 已挂载 `${CV_NODE_ROOT}/models:/models`，按新模板重建 Manager 即可。
- 在节点上构建镜像需要该节点能下载基础镜像和依赖；能从其他节点传输时优先传输。
