# 模型推理使用与部署说明

首期需求与验收范围见 [模型推理.md](../模型推理.md)。

## 页面入口

- **模型推理 → 推理中心**：选择任务类型、模型系列与版本，再选择图片、视频或实时来源。常用数字参数直接显示，完整参数按需展开。
- **模型推理 → 推理任务**：统一管理图片批次、视频与实时会话，查看结果和报告。
- 原 `/tasks` 单图任务、任务详情、结果对比与模型部署保留。高级编排保留旧媒体记录，新增媒体任务统一从推理中心创建。
- 部署实例、服务入口和训练模型试用的原链接可继续进入推理中心。

## 图片与视频

图片支持上传和资源库多选，每次最多 100 张。批次在服务端执行，刷新或离开页面后可在推理任务找回；失败与未处理图片可重新提交。

视频支持全帧处理（间隔设为 0）和按秒抽帧。时间轴按已处理帧索引选择，旁边显示源帧号和源时间。输出结果视频为 H.264 MP4，保留采样时间间隔，不含音轨；视频编码可能用重复画面表达时间间隔，编码帧数不作为处理帧数统计。

首期图片结果继续适配已有检测、分类、分割、OCR 和姿态展示组件。目标跟踪与检测框统计仅对目标检测开放；其他结果保留其原始 JSON 结构，不将非检测任务误称为检测精度评测。

## 实时来源与停止

- 浏览器摄像头：使用访问平台的电脑设备，需要浏览器授权及可使用摄像头的访问环境。localhost 可用于本机测试；远程访问部署应使用 HTTPS。关闭采集页面或超过 15 秒没有提供新画面，会话标记为中断。
- 服务器摄像头：采集发生在 Media Worker 所在服务器，来源使用 `camera:0` 等地址。不能将这里的编号理解成浏览器电脑的摄像头编号。
- RTSP：在当前项目登记地址后启动。服务端会话不会因关闭预览页面而结束，可在推理任务停止，也可以设置定时停止。
- 默认最多重连 3 次，最多可配置 5 次；重连采用有限退避，断流后建立新轨迹片段。
- 服务器重启会将未完成会话标记为中断，保留已有结果；需要用户重新启动。不会配置开机自动启动平台或自动恢复采集。

### 服务器摄像头映射

没有连接摄像头时不需要修改本机部署。具备设备后，将 [compose.camera.example.yaml](../compose.camera.example.yaml) 作为额外覆盖文件使用：

```bash
CV_PLATFORM_CAMERA_DEVICE=/dev/video0 docker compose \
  -f compose.yaml -f compose.database.yaml -f compose.local.yaml \
  -f compose.camera.example.yaml --profile database \
  up -d --no-deps --no-build media-worker
```

该示例只映射一个明确设备，不使用 privileged，不改变关闭开机自启动的策略。设备路径、访问权限和镜头画面需要在真实设备上验收；远程计算节点选择只控制推理执行位置，摄像头采集仍在已配置的 Media Worker。

## 跟踪与统计口径

首期跟踪采用按类别的贪心 IoU 关联：阈值 0.3，最长关联间隔 2 秒，展示最近 30 个位置。它是轻量的同路轨迹关联，不含身份识别或重识别。

- 轨迹标识由会话、连续片段和目标 ID 共同确定。
- 遮挡、快速运动、较大抽帧间隔、离开再进入及断流都可能产生新 ID。
- 当前检测框数、累计检测框数和累计轨迹数分别统计，均不能直接解释成去重人数。
- 没有真实标注时不生成准确率、召回率或 mAP；这些指标仍属于数据集评测流程。
- 实时输入超出处理能力时采用最新画面策略；“跳过源帧”包含采样与未处理源帧，不能直接当作网络丢包率。

## 报告与下载

任务详情支持在线查看，并提供：

- `summary.csv`：汇总指标及统计范围。
- `metrics.csv`：逐图片/逐帧检测结果、置信度、位置、轨迹及耗时等明细。
- `results.json`：包含各任务类型原始结果结构和跟踪信息的完整逐帧结果。
- `report.json`、PDF：任务、输入、模型来源、实际配置、执行位置、统计、图表、样例和完整性说明。
- PNG：统计图表、单帧结果图；结果视频和采样录像按实际生成情况提供。
- ZIP：报告、汇总/明细、图表、代表性样例和适用的完整会话视频，包含文件清单。

时间筛选采用相对源时间/会话时间的秒数，左闭右开。类别和展示置信度筛选作用于已保存结果，不能恢复模型阈值已过滤的目标。筛选报告不附带未筛选的样例或完整视频，避免下载范围混淆。

运行中的报告注明统计截止时间，后续刷新或下载可能得到更新的阶段快照。最终任务的网页与下载基于同一份持久化结果。大型逐帧 JSON、CSV 和 ZIP 使用分页读取及临时文件，下载后清理临时文件。

## 容量与保留策略

- 本机首期同时最多 2 个会话执行、最多 8 个活动/排队会话；单会话逐帧推进，避免一次提交全部视频帧。
- 浏览器实时采集需要空闲执行槽，待处理上传队列最多保留 1 帧，容量不足时返回可重试的背压响应。
- 默认最多处理 1000 帧，可配置到 10000 帧。实时任务默认 60 分钟停止，可设为 0（手动停止，但仍受帧数和容量上限限制）。
- 本次生成产物、输入及明细快照估算达到配置容量时停止继续采集；磁盘空闲不足 256 MB 时停止。视频编码会额外占用空间，编码失败在报告中明确说明。
- 生成预览、逐帧样例和视频默认保留 7 天，可配置为 1–90 天，每 5 分钟检查到期产物。共享上传资源和结构化任务数据不自动删除，需要另行管理。
- 源文件、采样画面和结果明细不能无限期当作免费存储；界面显示生成产物占用和保留截止时间，报告记录采集上限。

## YOLO26 推理

推理中心的「算法 / 模型系列」选择 **YOLO26**，再选择 **n / s / m / l / x** 对应的官方预训练模型或已发布的训练模型。官方预训练模型用于 COCO 80 类目标检测，显示独立来源信息；自定义类别请使用训练后发布的权重。五种规格共用图片、视频、摄像头、RTSP 会话与报告流程，视频和流输入可开启目标跟踪。

运行时沿用固定的 Ultralytics 8.4.183 / PyTorch 2.10 / CUDA 12.8。`nms` 等推理选项以此版本的参数契约为准，不把 YOLO26 一概当作只能使用免 NMS 模式；参见 [Ultralytics 推理模式说明](https://docs.ultralytics.com/guides/end2end-detection/)。

新机器完成数据库迁移、构建并启动 backend / worker / 通用 YOLO 镜像后，可安装本地官方权重：

```bash
bash scripts/install-yolo26-inference.sh
# 可选参数为包含 yolo26n/s/m/l/x.pt 的目录
# 指定项目：CV_PLATFORM_TARGET_PROJECT=<项目 UUID> bash scripts/install-yolo26-inference.sh
```

默认读取 `runtimes/yolo-trainer/assets/`，权重来源见该目录 README。安装器不联网、不启动模型容器、不加载 pickle；复制文件并记录 SHA-256，推理时按需加载和同步到执行节点。相同项目、版本和权重重复执行不会创建重复条目，不覆盖不同内容的既有版本，也不会重新启用已停用的模型。安装过程不更改开机启动配置。

2026-10-23 本机验收：五种规格分别在 GPU 上完成图片推理，均返回有效检测框；YOLO26n 视频抽帧处理 3 帧并生成 5 条轨迹，标注视频、CSV 汇总/明细、PDF 和完整 ZIP 下载成功。浏览器检查五规格可选、预训练来源正确且无脚本错误；安装器重复执行保留相同版本 ID。后端相关测试 15 项通过，前端训练来源回归测试、构建和 ESLint 通过。真实服务器摄像头和用户实际 RTSP 设备仍待设备可用后补测。

## 检测结果收集与审核（2026-10-24）

推理结果、单帧详情与历史任务支持“收集并审核”，进入资源库的“问题样本”队列。预测框仅作为待审核草稿，可修正类别、坐标、增删框；明确人工审核后才通过新网页流程生成训练数据新版本。评测来源保留原真实标注与评测关联，避免把模型预测直接当作真实标签；同图片不会因重复收集覆盖已有人工修改。

评测中心提供按模型、误检 / 漏检和类别查找问题图片、查看预测与真实框叠加的入口；多模型固定 IoU 指标与 YOLO 单模型 COCO mAP 验证区分展示。完整流程见 `docs/TRAINING.md`。


## Faster R-CNN 训练模型接入

算法统一为 Faster R-CNN ResNet50-FPN（`fasterrcnn_resnet50_fpn`）。在训练任务完成后点击发布，平台自动生成相配套的 model.pth、model-config.yaml、manifest.yaml，推理中心按 Faster R-CNN 算法分组选择该版本。无需手动修改分类头或类别编号；模型类别 0 是背景，数据类别映射到 1..N。

训练与推理共用 SDK 结构和预处理，推理严格检查权重类别顺序，NMS 按类别执行，结果返回已发布模型自己的 ID 与版本。新训练发布模型支持 CPU / GPU 自动设备选择；GPU 不可用时可使用 CPU 推理。旧官方裸权重的推理读取兼容保留，但训练端自定义上传须采用含结构/类别元数据的平台权重格式。参数和验收口径见 `docs/TRAINING.md`。
